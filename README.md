# NetDoctor 🩺

[![Tests](https://github.com/GAGAUTKA228/netdoctor/actions/workflows/tests.yml/badge.svg)](https://github.com/GAGAUTKA228/netdoctor/actions/workflows/tests.yml)

Быстрая диагностика сети из одной команды — то, что реально берёшь с собой на выезд.

Вместо того чтобы по очереди запускать `ping`, `tracert`/`traceroute`, `nslookup`,
`arp -a` и отдельный сканер портов, **NetDoctor** прогоняет всё за один вызов
и выводит результат в понятном, цветном виде — сразу видно, где именно проблема.

## Зачем это нужно

На выезде или в саппорте типичная ситуация: "не работает интернет / не открывается
1С / сервер недоступен". Дальше начинается ручная диагностика — минимум 5 команд
с разным синтаксисом под Windows и Linux. NetDoctor делает это одним запуском и
сразу отвечает на вопросы:

- Какая у меня самого сеть (IP, шлюз, DNS-серверы)?
- Резолвится ли имя в DNS?
- Есть ли целевой хост в моей ARP-таблице (L2-связность)?
- Отвечает ли хост на ping и сколько теряется пакетов?
- На каком хопе по пути рвётся маршрут?
- Какие порты открыты — жив ли нужный сервис (RDP, SMB, веб, БД...)?
- Не врёт ли мне сеть, показывая "все порты открыты" (детектор перехвата трафика)?

## Установка

Требуется Python 3.8+.

```bash
git clone https://github.com/GAGAUTKA228/netdoctor.git
cd netdoctor
pip install -r requirements.txt
```

Или установить как пакет (появится команда `netdoctor` в системе):

```bash
pip install -e .
netdoctor 192.168.1.1
```

## Использование

```bash
# Полная проверка со всеми портами по умолчанию
python netdoctor.py 192.168.1.1

# Проверка конкретного хоста, только нужные порты
python netdoctor.py example.com -p 22,80,443

# Диапазон портов
python netdoctor.py 192.168.1.10 -p 1-1024

# Пропустить traceroute (например, если он режется firewall'ом и долго висит)
python netdoctor.py server.local --no-trace

# Пропустить информацию о локальной сети и ARP-таблицу
python netdoctor.py server.local --no-info
```

Запуск без аргумента (например, двойным кликом по собранному `.exe`) —
скрипт сам спросит адрес интерактивно и не закроет окно, пока не нажмёшь Enter.

### Все параметры

| Параметр       | Описание                                              |
|----------------|--------------------------------------------------------|
| `target`       | Хост или IP (если не указан - спросит интерактивно)      |
| `-p, --ports`  | Список/диапазон портов, напр. `22,80,443` или `1-1024`   |
| `--count`      | Количество ping-пакетов (по умолчанию 4)                 |
| `--timeout`    | Тайм-аут на порт при сканировании в секундах (по умолчанию 0.7) |
| `--no-dns`     | Пропустить DNS-проверку                                  |
| `--no-ping`    | Пропустить ping                                          |
| `--no-trace`   | Пропустить traceroute                                    |
| `--no-ports`   | Пропустить сканирование портов                           |
| `--no-info`    | Пропустить локальную сетевую информацию и ARP-таблицу    |

## Портативный .exe (без установки Python на целевой машине)

Если нужно запускать NetDoctor на компьютерах сотрудников без установки
Python, собери его в один исполняемый файл через
[PyInstaller](https://pyinstaller.org/). Собирать нужно **на Windows**
(кросс-сборка из Linux/macOS для Windows не поддерживается официально),
но собранный `.exe` потом можно копировать и запускать на любой другой
Windows-машине без Python вообще.

Есть готовый скрипт `build.bat`, который делает всё одной командой:

```bash
build.bat
```

Готовый файл появится в `dist\netdoctor.exe`. Запуск:

```bash
netdoctor.exe 192.168.1.10 -p 22,80,443
```

### Возможные нюансы

- **Антивирус/Windows Defender** иногда помечает exe-файлы, собранные
  PyInstaller, как подозрительные (известное ложное срабатывание, а не
  признак реального вредоносного кода). Добавь в исключения при необходимости.
- Первый запуск `.exe` может быть на 1-2 секунды медленнее — PyInstaller
  распаковывает Python-рантайм во временную папку при старте.
- Собранный `.exe` работает только на той разрядности Windows, на которой
  собирался (обычно x64).

## Тестирование

```bash
pip install -r requirements.txt -r requirements-dev.txt
pytest -v
```

Тесты покрывают чистую логику (разбор портов, декодирование консольного
вывода, детектор перехвата сети, DNS-резолвинг) через моки — без обращения
к реальной сети, поэтому прогоняются одинаково быстро и локально, и в CI.
При каждом push на GitHub тесты автоматически прогоняются на Python 3.9,
3.11 и 3.12 (см. бейдж вверху README).

## Как это устроено

- **DNS** — стандартный модуль `socket` (`gethostbyname` / `gethostbyaddr`),
  без внешних зависимостей.
- **Ping / traceroute / ARP / сетевая информация** — скрипт определяет ОС
  через `platform.system()` и вызывает системные утилиты с правильными для
  этой ОС флагами (`ping -n`/`-w` на Windows, `-c`/`-W` на Linux). Вывод
  Windows-консоли (кодировка CP866) декодируется отдельной функцией, чтобы
  кириллица не превращалась в кракозябры.
- **Сканер портов** — свои TCP-коннекты через `socket.connect_ex()` в
  несколько потоков (`ThreadPoolExecutor`), с автоматической проверкой
  "порта-канарейки" для обнаружения сетей, перехватывающих весь TCP-трафик
  (корпоративные firewall/прокси с SSL-инспекцией, VPN, капитал-порталы).

## "Все порты открыты" — это баг или сеть?

Если сканер показывает открытыми **вообще все** порты, включая заведомо
экзотические (VNC, MSSQL, Telnet) — это почти всегда не ошибка скрипта,
а означает, что сеть между вами и целью **перехватывает все TCP-соединения**
независимо от порта. NetDoctor детектирует это автоматически через
"порт-канарейку" и выводит явное предупреждение, если результатам
сканирования нельзя доверять.

## Известные ограничения

- `traceroute` на некоторых Linux-системах требует `sudo` или отдельной
  установки пакета (`apt install traceroute`).
- Сканер портов проверяет только TCP; UDP-порты не проверяются.
- Это инструмент быстрой диагностики, а не замена полноценному сканеру
  безопасности (nmap, Zenmap и т.п.).
