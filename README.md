# NetDoctor 🩺

Быстрая диагностика сети из одной команды — то, что реально берёшь с собой на выезд.

Вместо того чтобы по очереди запускать `ping`, `tracert`/`traceroute`, `nslookup` и
отдельный сканер портов (который ещё и не всегда разрешено ставить на рабочий ноут),
**NetDoctor** прогоняет всё за один вызов и выводит результат в понятном,
цветном виде — сразу видно, где именно проблема.

## Зачем это нужно

На выезде или в саппорте типичная ситуация: "не работает интернет / не открывается
1С / сервер недоступен". Дальше начинается ручная диагностика — минимум 4 команды
с разным синтаксисом под Windows и Linux. NetDoctor делает это одним запуском и
сразу отвечает на вопросы:

- Резолвится ли имя в DNS?
- Отвечает ли хост на ping и сколько теряется пакетов?
- На каком хопе по пути рвётся маршрут?
- Какие порты открыты — жив ли нужный сервис (RDP, SMB, веб, БД...)?

## Пример вывода

```
NetDoctor -> цель: example.com

DNS: example.com
================
[OK]   example.com -> 93.184.216.34
[OK]   Обратный DNS (PTR): 93.184.216.34 -> example.com

PING: example.com
==================
[OK]   example.com отвечает на ping

TRACEROUTE: example.com
========================
...
[OK]   Трассировка завершена

ПОРТЫ: 93.184.216.34 (21 шт.)
==============================
[OK]   Порт 80 открыт (HTTP)
[OK]   Порт 443 открыт (HTTPS)
Проверено 21 портов за 1.4 сек.

Готово.
```

## Установка

Требуется Python 3.7+.

```bash
git clone https://github.com/GAGAUTKA228/netdoctor.git
cd netdoctor
pip install -r requirements.txt
```

Цветной вывод работает через `colorama` (нужна в основном для старых версий
Windows). Если её не установить, скрипт всё равно работает — просто без цвета.

## Использование

```bash
# Полная проверка со всеми портами по умолчанию
python3 netdoctor.py 192.168.1.1

# Проверка конкретного хоста, только нужные порты
python3 netdoctor.py example.com -p 22,80,443

# Диапазон портов
python3 netdoctor.py 192.168.1.10 -p 1-1024

# Пропустить traceroute (например, если он режется firewall'ом и долго висит)
python3 netdoctor.py server.local --no-trace

# Только ping и DNS, без сканирования портов
python3 netdoctor.py server.local --no-ports --no-trace
```

### Все параметры

| Параметр       | Описание                                              |
|----------------|--------------------------------------------------------|
| `target`       | Хост или IP (обязательный)                              |
| `-p, --ports`  | Список/диапазон портов, напр. `22,80,443` или `1-1024`   |
| `--count`      | Количество ping-пакетов (по умолчанию 4)                 |
| `--timeout`    | Тайм-аут на порт при сканировании в секундах (по умолчанию 0.7) |
| `--no-dns`     | Пропустить DNS-проверку                                  |
| `--no-ping`    | Пропустить ping                                          |
| `--no-trace`   | Пропустить traceroute                                    |
| `--no-ports`   | Пропустить сканирование портов                           |

## Как это устроено

- **DNS** — стандартный модуль `socket` (`gethostbyname` / `gethostbyaddr`), без
  внешних зависимостей.
- **Ping / traceroute** — скрипт определяет ОС через `platform.system()` и
  вызывает системные утилиты с правильными для этой ОС флагами
  (`ping -n`/`-w` на Windows, `-c`/`-W` на Linux).
- **Сканер портов** — свои TCP-коннекты через `socket.connect_ex()` в
  несколько потоков (`ThreadPoolExecutor`), поэтому даже 1000 портов
  проверяются за разумное время без установки nmap.

## Портативный .exe (без установки Python на целевой машине)

Если нужно запускать NetDoctor на компьютерах сотрудников без установки
Python, собери его в один исполняемый файл через
[PyInstaller](https://pyinstaller.org/). Собирать нужно **на Windows**
(кросс-сборка из Linux/macOS для Windows не поддерживается официально),
но собранный `.exe` потом можно копировать и запускать на любой другой
Windows-машине без Python вообще.

Сборка (один раз, на своей машине):

```bash
pip install pyinstaller
pyinstaller --onefile --console --name netdoctor netdoctor.py
```

Готовый файл появится в `dist\netdoctor.exe`. Его можно скопировать на
флешку, в общую сетевую папку или на конкретный ПК — запускается двойным
кликом или из cmd:

```bash
netdoctor.exe 192.168.1.10 -p 22,80,443
```

Есть готовый скрипт `build.bat`, который делает то же самое одной командой
(см. ниже).

### Возможные нюансы

- **Антивирус/Windows Defender** иногда помечает exe-файлы, собранные
  PyInstaller, как подозрительные (ложное срабатывание — это известная
  особенность самого PyInstaller, а не признак реального вредоносного кода).
  Если корпоративный антивирус блокирует запуск — добавь файл в исключения
  или собери и подпиши exe корпоративным сертификатом, если такой есть.
- Первый запуск `.exe` может быть на 1-2 секунды медленнее обычного —
  PyInstaller распаковывает Python-рантайм во временную папку при старте.
- Собранный `.exe` работает только на той разрядности Windows (обычно
  x64), на которой собирался.



- `traceroute` на некоторых Linux-системах требует `sudo` или отдельной
  установки пакета (`apt install traceroute`).
- Сканер портов проверяет только TCP; UDP-порты (например, часть DNS-трафика)
  не проверяются.
- Это инструмент быстрой диагностики, а не замена полноценному сканеру
  безопасности (nmap, Zenmap и т.п.).

## "Все порты открыты" — это баг или сеть?

Если сканер показывает открытыми **вообще все** порты, включая заведомо
экзотические (VNC, MSSQL, Telnet) — это почти всегда не ошибка скрипта,
а означает, что сеть между вами и целью **перехватывает все TCP-соединения**
независимо от порта. Так ведут себя корпоративные firewall/прокси с
SSL-инспекцией (Zscaler, FortiGate и т.п.), VPN-клиенты с перехватом
трафика или капитал-порталы Wi-Fi.

NetDoctor детектирует это автоматически: перед сканированием он проверяет
заведомо случайный высокий порт (49152-65000), которого нет в списке
запрошенных. Если этот "порт-канарейка" тоже оказывается "открыт" —
выводится предупреждение, что результатам сканирования доверять нельзя.
В этом случае корректная диагностика возможна только из сети без такого
перехвата (например, из дома или через мобильный интернет).
